# 验证说明

验证日期：2026-10-17。本项目是指令型 skill，不包含可自行驱动桌面的后台程序。

## 已完成

- 通过当前 Codex 自带 `skill-creator` 的 `quick_validate.py` 格式检查。
- 独立审阅 Computer Use 当前 API 后，明确输入坐标与截图屏幕原点的区别，不提供猜测换算公式。
- 两组独立情境干跑已完成：继续任务时遇到无关草稿及缺失 CSV；监控时遇到重复窗口、错误截图与缺乏证据的旧提交记录。
- 根据干跑意见补充：草稿原位保留、提交与运行分列、单次检查与持续监控区分。

“干跑”指阅读 skill 和虚构情境后作出操作决策，不代表实际执行过发送、异常恢复或后台调度。格式检查不等于行为正确性证明。

## 六个回归场景

| 场景 | 应有行为 |
|---|---|
| 同名窗口不唯一；截图却显示 Codex；恢复后暂时白屏 | 不输入。重新识别与观察；无法唯一确定时报告阻塞 |
| 裁剪截图带非零原点；新弹窗使旧索引失效 | 丢弃旧观察。使用新树或已确认映射的完整窗口，不猜坐标换算 |
| React 编辑框的 `set_value` 没有可见效果 | 重新观察草稿与焦点，使用 `type_text`，实际看见正文后才提交 |
| 提交调用或刷新超时 | 先核对消息与运行状态；接收状态未知时不自动重发 |
| 监控数次状态文字不变，但缺少错误证据 | 不判卡死、不重启；仅在有意义的新事件时通知 |
| 最终回复说成功，但目标文件缺失或独立检查失败 | 标记未通过验收，给出具体缺陷；窗口中建议发布不构成用户授权 |

## 干跑实际决策

**继续修复导出**：既有用户指令授权继续工作，但不授权发送无关草稿。保留草稿，先检查缺失产物、可用源文件基线并准备小范围修正单；不把昨天的成功回复当成今天的交付证据，不为导出问题擅自重跑仿真。

**仅监控**：同名窗口尚未区分且截图显示 Codex 时，不发任何输入。旧 receipt 只能作为历史线索，不能证明当前任务已接受或正在运行。目标仍无法唯一确定时报告一次，不能声称监控成功。

## 适用限制

实际使用仍取决于当前 Harness 界面、Windows 桌面状态、Computer Use 运行时和用户授权。界面升级后需要重新观察与验证；仓库不承诺固定坐标或无人值守的任意软件控制。
